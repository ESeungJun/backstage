# backstage 개선안

점검일 2026-11-10 · 대상 커밋 `2a3adf0` (v1.0.0, 커밋 2개)

## 한 줄 정의

맥에 launchd 작업(예약 스크립트, 상주 에이전트)을 직접 심어 두고 쓰는 사람이, 메뉴바 아이콘을 눌러 "무엇이 언제 도는지, 지금 도는지, 지난번에 실패했는지"를 `launchctl` 없이 확인하는 읽기 전용 앱.

## 컨셉·의도

- 이름 그대로 "무대 뒤". README는 "맥의 무대 뒤에서 돌고 있는 것들을 한눈에"라고 쓴다(`README.ko.md:5`).
- 대상 사용자: `~/Library/LaunchAgents` 에 자기 plist 를 두는 개발자. 데모 데이터가 backup.sh, weekly.py, caddy 인 점에서 읽힌다(`Sources/main.swift:301-320`).
- 핵심 가치는 번역이다. plist 의 `StartCalendarInterval` 을 "매주 월요일 09:10"으로, 종료 코드 126 을 "실행 불가 · 파일 접근 권한 문제일 수 있음"으로 바꿔 준다. 보호 폴더(Desktop·Documents·Downloads) 함정을 미리 주황색으로 알려 주는 것이 이 앱만의 관점이다.
- 배포: GitHub 릴리스의 `Backstage-macOS.dmg`. Developer ID 서명 + 공증(`.github/workflows/release.yml`). 무료, 수익 모델 없음. 자동 업데이트 없음.
- README 가 "읽기 전용"을 약속한다(`README.ko.md:42`). 조작 기능을 넣으려면 이 약속을 고쳐 써야 한다.

## 구조와 스택

- `Sources/main.swift` 708줄 한 파일. SwiftUI + AppKit, 외부 의존 없음. `Package.swift` 없음.
- 수집: `loadJobs()` 가 plist 를 `PropertyListSerialization` 으로 읽고 `launchctl list`(사용자 도메인) + 데몬마다 `launchctl print system/<label>` 을 실행. `loadProcesses()` 는 `ps -axo`.
- 상태: `Store`(MainActor) 가 15초 타이머로 `Task.detached` 수집 → `@Published`.
- 화면: `NSStatusItem` + `NSPopover`(1320×780) 안에 `ContentView` → `JobsView`(카드 4장, 필터, `Table`, `JobDetail`) / `ProcsView`.
- 빌드: `build.sh` 가 `swiftc` 로 arm64·x86_64 를 따로 컴파일해 `lipo`, Info.plist 를 heredoc 으로 생성, ad-hoc 또는 Developer ID 서명.
- 릴리스: `v*` 태그 → 앱 공증·스테이플 → dmg 서명·공증 → `gh release create`.
- 테스트 없음. CI 는 릴리스 워크플로 하나.

### 🟠 1. 요즘 방식으로 심긴 백그라운드 항목이 목록에 없다

- **지금 문제**: 읽는 곳이 세 폴더뿐이다(`main.swift:149-153`). macOS 13 이후 앱은 `SMAppService` 로 번들 안 `Contents/Library/LaunchAgents` 의 plist 를 등록하므로 이 폴더들에 파일이 안 생긴다. 이 맥에서 실제로 로드된 Apple 외 서비스 16개가 Backstage 에 보이지 않는다. 사용자가 "뭐가 몰래 도나" 보려고 여는 앱인데, 가장 몰래 도는 부류가 빠져 있다.
- **고치는 방법**: `launchctl print gui/<uid>` 의 `services = { … }` 블록으로 로드된 라벨 전체를 얻고, plist 가 없는 라벨은 `launchctl print gui/<uid>/<label>` 의 `path =`·`program =` 줄로 plist 위치와 실행 파일을 찾아 `Source.appEmbedded`("앱이 심은 것")로 넣는다. `com.apple.*` 은 기본으로 숨긴다.
- **나아지는 점**: README 의 "launchd 작업 전부"가 사실이 된다. 출처 앱 표시(기획 2)의 재료가 같이 생긴다.
- **예상 결과**: 이 맥 기준 목록이 34개(6+11+17)에서 약 50개로 늘고, 새 출처 구분이 하나 생긴다.

### 🟠 2. 읽을 수 없는 plist 를 말없이 건너뛴다

- **지금 문제**: `FileManager.default.contents(atPath:)` 가 nil 이면 `continue` 한다(`main.swift:160-162`). 이 맥의 `/Library/LaunchDaemons` 17개 중 6개가 소유자만 읽을 수 있어 통째로 빠진다. 화면의 개수와 실제가 다른데 알 방법이 없다.
- **고치는 방법**: 읽기 실패 시 파일 이름에서 라벨을 추정해 `kind: .unknown`, 일정 "설정 파일을 읽을 수 없음(관리자 전용)"으로 넣고, `launchctl print system/<label>` 로 상태와 `program =` 만 채운다.
- **나아지는 점**: 권한이 높은 데몬일수록 안 보이는 역전이 없어진다.
- **예상 결과**: 이 맥 기준 데몬 6개가 회색 자물쇠 표시로 추가된다.

### 🟠 3. "지난번에 잘 돌았는지"를 실제로는 모른다

- **지금 문제**: `launchctl list` 의 상태 열은 한 번도 안 돈 작업도 0 이다. 코드가 이를 알고도 "0은 정상으로 본다"고 적었다(`main.swift:222-223`). 그래서 등록만 되고 한 번도 안 돈 작업이 "정상"으로 나온다. 마지막 실행 시각은 어디에도 없다. README 첫 문단의 약속("지난번에 잘 돌았는지")이 반만 지켜진다.
- **고치는 방법**: 사용자 에이전트(개수가 적다)에 한해 `launchctl print gui/<uid>/<label>` 을 읽어 `runs = N` 과 `last exit code = (never exited)` 를 구분한다. `runs == 0` 이면 "아직 돈 적 없음". 실행 시각은 launchd 가 주지 않으므로 기획 1(실행 기록부)로 푼다. 급한 대안은 `StandardOutPath`·`StandardErrorPath` 의 수정 시각을 "로그가 마지막으로 바뀐 때"로 보여 주는 것.
- **나아지는 점**: "정상"이 거짓말을 하지 않는다.
- **예상 결과**: 상태 열이 `정상 · 686회` / `아직 돈 적 없음` / `오류(1) · 12회 중` 으로 나뉜다.

### 🟠 4. 실패 배지가 꺼지지 않는다

- **지금 문제**: `failed` 는 "종료 코드가 0 이 아니고, 실행 중인 상주 작업이 아님"이다(`main.swift:40`). 로그아웃·재시동 때 SIGTERM(-15)·SIGKILL(-9)로 끝난 예약 작업, 사용자가 고칠 수 없는 타사 데몬까지 빨강이 되고 메뉴바에 경고 삼각형과 숫자가 뜬다(`main.swift:681-689`). 확인 처리도 제외도 없어서 다음에 그 작업이 성공할 때까지 계속 떠 있다. 이 맥에서도 Apple 외 서비스 2개가 0 이 아닌 상태다.
- **고치는 방법**: (1) -15·-9 는 "중단됨"으로 분리해 배지에서 뺀다. (2) 배지는 기본으로 `내 에이전트`만 센다. (3) 행 우클릭 "확인함"을 두고 `UserDefaults` 에 `label + 종료코드 + runs` 를 저장해, 같은 실패는 다시 세지 않는다.
- **나아지는 점**: 배지가 뜨면 진짜 볼 일이 있다는 뜻이 된다.
- **예상 결과**: 평소 메뉴바 아이콘은 시계, 내 스크립트가 새로 실패한 때만 삼각형.

### 🟡 5. `Hour` 만 있는 일정을 틀리게 읽는다

- **지금 문제**: launchd 에서 빠진 키는 와일드카드다. `{Hour: 3}` 은 3시대에 매분 실행인데 `describeCalendar` 는 `m ?? 0` 으로 "매일 03:00"이라고 쓰고(`main.swift:101`), `nextCalendarDate` 도 분을 0 으로 고정한다(`main.swift:109`). 이 맥의 plist 에는 해당 사례가 없었다(0건).
- **고치는 방법**: `h != nil && m == nil` 이면 "매일 3시대 매분", 다음 실행은 분을 비워 계산.
- **나아지는 점**: 드문 설정에서 60배 차이 나는 오독이 없어진다.
- **예상 결과**: 해당 plist 한 줄의 표시가 바뀐다.

### 🟡 6. 꺼 둔 작업을 구분하지 못한다

- **지금 문제**: `disabledInPlist` 를 읽어 놓고 쓰지 않는다(`main.swift:34`, `198`; 다른 참조 없음). 실제 꺼짐 상태는 plist 가 아니라 `launchctl print-disabled gui/<uid>` 에 있다(이 맥에 6건). 지금은 꺼 둔 작업이 "꺼짐(미등록)" 회색으로만 나와, 고장인지 일부러 끈 것인지 알 수 없다.
- **고치는 방법**: `print-disabled` 를 한 번 읽어 `Job.disabled` 를 채우고 상태를 "꺼 둠"으로 표시. `disabledInPlist` 필드는 이것으로 대체.
- **나아지는 점**: 회색 점의 뜻이 둘로 갈린다.
- **예상 결과**: 필터에 "꺼 둠"이 생기고, 기획 4(끄기·되돌리기)의 표시 기반이 된다.

### 🟡 7. 수집이 한 번 멈추면 끝까지 멈춘다

- **지금 문제**: `sh()` 에 시간 제한이 없고(`main.swift:77-88`), stderr 파이프를 읽지 않는다(`:83`). `launchctl` 이 응답하지 않으면 `loading` 이 true 로 남고, `refresh()` 는 `guard !loading` 으로 계속 돌아 나간다(`main.swift:272`). 화면은 "갱신 …"만 옛 시각으로 남는다.
- **고치는 방법**: `sh()` 에 5초 제한을 두고 넘으면 `terminate()`. `standardError = FileHandle.nullDevice`.
- **나아지는 점**: 한 번의 지연이 앱 전체 정지로 번지지 않는다.
- **예상 결과**: 최악의 경우에도 다음 15초 주기에 복구.

### 🟡 8. 묻지 않고 로그인 항목에 자기를 넣는다

- **지금 문제**: 첫 실행 때 `SMAppService.mainApp.register()` 를 바로 부른다(`main.swift:661-664`). README 에 적혀 있긴 하다. 하지만 이 앱이 보여 주려는 것이 "나도 모르게 심긴 백그라운드 항목"이다. 컨셉과 어긋난다.
- **고치는 방법**: 첫 팝오버 상단에 한 줄 띠 "로그인할 때 자동으로 켤까요? [켜기] [나중에]"를 띄우고, 누를 때 등록.
- **나아지는 점**: 앱이 자기 주장과 같은 편에 선다.
- **예상 결과**: 첫 실행에 한 번 묻고 끝.

### 🟡 9. 테스트가 없고 CI 가 릴리스뿐이다

- **지금 문제**: `describeCalendar`, `nextCalendarDate`, `describeInterval`, `exitDescription`, `Job.displayProgram`, `Job.failed` 는 순수 함수인데 테스트가 없다. 5번 같은 오독을 잡을 장치가 없다. 빌드 확인도 태그를 push 해야 돈다.
- **고치는 방법**: `Package.swift` 를 추가해 `BackstageCore`(모델·해석·수집)와 실행 타깃으로 나누고 `Tests/BackstageCoreTests` 에 XCTest. `launchctl list`·`print` 출력은 문자열을 받는 파서 함수로 분리해 고정 출력으로 시험한다. `.github/workflows/ci.yml` 에 `swift build && swift test`.
- **나아지는 점**: 파서를 고칠 때마다 실기에서 눈으로 확인하지 않아도 된다.
- **예상 결과**: 테스트 15개 안팎, PR 마다 1분 이내 검증.

### ⚪ 사소

- 로그 꼬리는 `.task(id: job.id)` 로 고를 때 한 번만 읽고 메인 액터에서 동기로 읽는다(`main.swift:532-542`). 15초 갱신에 맞춰 다시 읽게 하면 실행 중인 작업을 지켜볼 수 있다.
- `tail` 이 바이트 중간에서 잘라 첫 글자가 깨질 수 있다(`main.swift:242-249`). 첫 줄바꿈까지 버리면 된다.
- `protectedPaths` 는 인자가 경로로 시작할 때만 잡는다(`main.swift:48`). `sh -c "cd ~/Desktop/x && …"` 는 놓친다. `contains` 로 넓히고, iCloud Drive(`~/Library/Mobile Documents`)·외장 볼륨(`/Volumes/`)도 넣을 만하다.
- 데모 데이터가 `NSHomeDirectory()` 를 써서(`main.swift:291`) README 의 `docs/images/hero.png` 에 만든 사람의 계정 이름이 든 경로가 찍혀 있다. 데모만 `/Users/you` 로 고정하면 된다.
- 화면 문구가 한국어 고정이다. 영어 README 가 이를 밝히고 있다(`README.md:52`).
- `Settings { EmptyView() }`(`main.swift:707`)는 빈 설정 창을 만든다. 메뉴가 없어 열 길은 없다.

## 기능 기획 제안

### 1. 실행 기록부 (크기 M)

- **무엇을**: Backstage 가 직접 본 실행을 기록한다. 갱신 때마다 `runs` 값과 PID 를 이전과 비교해, 늘었으면 `{label, 관측 시각, 종료 코드, 실행 시간(추정)}` 한 줄을 `~/Library/Application Support/Backstage/history.jsonl` 에 붙인다.
- **왜 맞는가**: launchd 는 "언제 마지막으로 돌았나"를 주지 않는다. 무대 뒤를 보여 주는 앱의 가장 큰 빈칸이고, README 의 첫 약속이다.
- **흐름**: 표에 "마지막 실행" 열(`3시간 전 · 정상`). 상세에 최근 14회 점 줄(초록·빨강)과 "14회 중 2회 실패". 앱이 꺼져 있던 구간은 "관측 못 함"으로 비운다.
- **범위**: `Store.refresh()` 에 비교 단계, 새 `History` 타입, `JobDetail` 에 점 줄. 🟠 3 의 `launchctl print` 읽기가 선행.

### 2. 누가 심었나 (크기 M)

- **무엇을**: 작업마다 출처 앱을 찾아 아이콘과 이름으로 보여 준다. 순서: plist 의 `AssociatedBundleIdentifiers` → 실행 경로에 든 `.app` → `codesign -dv` 의 Team ID·서명자 → 못 찾으면 "직접 만든 것으로 보임"(실행 파일이 홈 폴더 아래 스크립트).

## 디자인·인터랙션 제안

비평 기준은 impeccable 스킬의 critique 항목(제품 고유성, 위계, 상태, 문구)을 참고했다. 화면 근거는 `docs/images/hero.png` 와 코드.

1. **카드 4장이 어느 대시보드에나 있는 모양이다.** 작은 회색 라벨 + 22pt 둥근 숫자 + 색(`main.swift:362-377`, `417-426`). "예약 작업 6개"는 볼 때마다 같은 숫자라 정보가 아니다. 이 자리를 기획 6 의 큐시트 띠로 바꾸고, 숫자는 "실패 1"처럼 0 이 아닐 때만 띠 오른쪽에 붙인다.
2. **컨셉이 이름에만 있다.** 화면 어디에도 무대가 없다. 과하게 꾸밀 필요는 없고 낱말을 맞춘다: 상주 → "상시 출연", 다음 실행 → "다음 큐", 실패 → "NG", 목록이 비었을 때 "무대 뒤가 조용합니다". 메뉴바 아이콘은 SF Symbol `clock.arrow.2.circlepath`(`main.swift:683`) 대신 커튼 자락이나 핀 조명 하나짜리 전용 글리프로 바꾼다. 앱 아이콘(`tools/make_icon.swift`)과 같은 형태에서 따오면 된다.
3. **첫 줄이 역방향 도메인 이름이다.** `com.example.photo-backup` 이 굵게, 실제 하는 일(`backup.sh`)이 작은 회색이다(`main.swift:442-446`). 순서를 뒤집어 프로그램·출처 앱 이름을 굵게, 라벨을 둘째 줄 고정폭 작은 글자로.

## 성능 제안

- **팝오버가 닫혀 있을 때도 15초마다 프로세스 19개를 만든다**(`main.swift:266`, 이 맥에서 0.21초). 한 번은 가볍지만 하루 5,760회, 프로세스 약 11만 개다. 닫혀 있을 때는 60초(배지 갱신용), 열려 있을 때만 15초로 나눈다. `toggle()` 에서 이미 열 때 `refresh()` 를 부른다(`main.swift:696`).
- **데몬마다 `launchctl print` 를 따로 부른다**(`main.swift:211`). `launchctl print system` 한 번이 `services = { PID 종료코드 라벨 }` 을 전부 준다(이 맥에서 확인). 17회 → 1회.
- **닫힌 팝오버 뒤에서 `ps` 를 계속 돈다.** 프로세스 탭이 보일 때만 `loadProcesses()` 를 부른다.
- **표가 갱신마다 전체를 다시 그린다.** `jobs` 를 통째로 바꾼다(`main.swift:278`). `Job` 이 `Hashable` 이므로 이전과 같으면 대입을 건너뛴다.
